# แผนงานการพัฒนา AI Interactive Learning เพื่อฝึกทักษะการสื่อสารในชีวิตประจำวัน
**กรณีศึกษาตัวอย่าง:** การสั่งเครื่องดื่มในร้านกาแฟ (Cafe Ordering Simulation)

---

## 1. บทนำและเป้าหมายโครงการ (Project Overview)

ระบบ **AI Interactive Learning for Daily Communication** มีเป้าหมายเพื่อช่วยให้ผู้เรียนสามารถฝึกฝนและพัฒนาทักษะการสื่อสารที่จำเป็นต่อการใช้ชีวิตจริง โดยเฉพาะการสื่อสารแบบผสมผสาน (**Multimodal Communication**) ที่ไม่ได้จำกัดเพียงการพูดเท่านั้น แต่ครอบคลุมถึง:
* **การพูด (Verbal):** การออกเสียง ความชัดเจน ความสุภาพ และการใช้ระดับภาษา
* **การชี้/การสัมผัส (Gestural/Pointing/AAC):** การใช้ท่าทางชี้เมนู หรือเลือกรูปภาพแทนคำพูด
* **การพิมพ์ (Textual):** การเขียนสื่อสารในกรณีที่ไม่สะดวกใช้เสียง

ระบบจะจำลองสภาพแวดล้อมเสมือน (Situational Simulation) โดยมี AI สวมบทบาทเป็นคู่สนทนา (เช่น บาริสต้า) ตอบสนองตามอินพุตที่ผู้เรียนส่งเข้ามาแบบ Real-time พร้อมทั้งวิเคราะห์และให้คำแนะนำในการปรับปรุงทักษะ

## 2. สถาปัตยกรรมระบบ (System Architecture)

```
[ผู้เรียน (User)]
      │
      ├─► เสียงพูด (Voice) ───────────► Web Speech API / Whisper STT ──┐
      ├─► การพิมพ์ (Text) ────────────► Chat Input ─────────────────────┼─► [Context Aggregator]
      └─► การชี้/แตะ (Touch/Pointer) ──► Interactive Menu Event ────────┘         │
                                                                                 ▼
                                                                       [Orchestrator Backend]
                                                                       (State Machine + Session)
                                                                                 │
                                                                                 ▼
                                                                       [LLM Decision Engine]
                                                                                 │
                                                  ┌──────────────────────────────┴──────────────────────────────┐
                                                  ▼                                                             ▼
                                     [Barista Persona Engine]                                         [Coach & Evaluation Engine]
                                     - บทสนทนาตอบกลับ (Text/Speech)                                   - วิเคราะห์ความชัดเจน (Clarity)
                                     - การแสดงท่าทาง/สถานะ (Action State)                             - วิเคราะห์ความเหมาะสม (Contextual Fit)
                                     - ระบบ Text-to-Speech (TTS)                                      - บันทึกความก้าวหน้า (Score & Log)
```

## 3. กลไกการประมวลผล Multimodal (Context Aggregation)

หัวใจของระบบคือการรวม **"ท่าทาง" (Action)** เข้ากับ **"คำพูด/ข้อความ" (Dialogue)** ก่อนส่งเข้าสู่โมเดล AI

### รูปแบบโครงสร้างข้อมูลที่ส่งเข้า AI (Payload Example)
```json
{
  "session_id": "usr_10293",
  "scenario": "cafe_counter",
  "environment_factors": {
    "noise_level": "medium",
    "queue_status": "busy"
  },
  "current_turn": {
    "user_speech": "ขอหวานน้อยแก้วนึงครับ",
    "user_text": "",
    "user_action": {
      "type": "point",
      "target_id": "menu_iced_latte",
      "target_label": "ลาเต้เย็น"
    }
  },
  "dialogue_history": [
    { "role": "barista", "content": "สวัสดีครับ รับอะไรดีครับ?" }
  ],
  "order_state": {
    "item": null,
    "temperature": null,
    "sweetness": null,
    "size": null,
    "is_complete": false
  }
}
```

## 4. ตารางตัวอย่างสถานการณ์และการตอบสนอง (Interaction Scenarios)

| รูปแบบอินพุตของผู้เรียน | ข้อมูลที่ระบบตรวจจับ | ผลลัพธ์และปฏิกิริยาของ AI บาริสต้า | การประเมินผลโดย Coach |
|---|---|---|---|
| **ชี้เมนู** (แตะที่ลาเต้เย็น) + **พูด** ("หวานน้อยแก้วหนึ่งครับ") | Target: `iced_latte`<br>Speech: `หวานน้อย 1 แก้ว` | "ได้ครับ ลาเต้เย็น หวานน้อย 1 แก้ว ไซส์ปกติ 60 บาทครับ" | **ดีเยี่ยม:** ใช้การชี้เสริมคำพูด ช่วยลดความกำกวมได้อย่างรวดเร็ว |
| **ชี้เมนูอย่างเดียว** (ไม่พูด ไม่พิมพ์) | Target: `hot_americano`<br>Speech: `null` | บาริสต้ามองตามมือ: "รับเป็นอเมริกาโน่ร้อนตัวนี้นะครับ รับขนาดไหนดีครับ?" | **ดี (ระดับพื้นฐาน/AAC):** สื่อสารสำเร็จ แนะนำให้ฝึกออกเสียงชื่อเมนูเพิ่ม |
| **พูดกำกวม** ("เอากาแฟแก้วนึง") | Target: `none`<br>Speech: `เอากาแฟแก้วนึง` | "ทางร้านมีทั้งเอสเปรสโซ ลาเต้ คาปูชิโน่ ลูกค้ารับเป็นกาแฟประเภทไหนดีครับ?" | **ต้องปรับปรุง:** ขาดรายละเอียดชนิดเครื่องดื่ม ทำให้ต้องถามซ้ำ |
| **พิมพ์ข้อความ** ("แพ้นมวัว ใช้นมโอ๊ตแทนได้ไหม") | Target: `none`<br>Text: `แพ้นมวัว ใช้นมโอ๊ต...` | "ได้เลยครับ ทางร้านมีนมโอ๊ตบวกเพิ่ม 15 บาท รับเป็นเมนูไหนดีครับ?" | **ดีเยี่ยม:** สื่อสารเงื่อนไขเฉพาะตัวได้ชัดเจน เหมาะกับสถานการณ์ |

## 5. แผนการพัฒนาตามระยะเวลา (Development Roadmap)

### เฟสที่ 1: การออกแบบระบบและฐานข้อมูลสถานะ (สัปดาห์ที่ 1 - 2)
* กำหนด Domain Ontology ของร้านกาแฟ (เมนู, ตัวเลือกความหวาน, ขนาด, ท็อปปิ้ง)
* พัฒนา State Machine สำหรับติดตามสถานะออเดอร์ (Slot Filling)
* ออกแบบ System Prompt แยกส่วน **Barista Persona** และ **Coach Evaluator**

### เฟสที่ 2: ระบบ Multimodal Front-End & Input Pipeline (สัปดาห์ที่ 3 - 4)
* พัฒนา UI หน้าเคาน์เตอร์ร้านกาแฟ และ Interactive Menu Board ที่คลิก/แตะได้
* เชื่อมต่อ Speech-to-Text (STT) และ Text-to-Speech (TTS)
* พัฒนาระบบรวม Event (คลิกชี้ + เสียงพูด) ส่งไปยัง Backend

### เฟสที่ 3: ระบบประเมินผลและ Feedback Engine (สัปดาห์ที่ 5 - 6)
* วิเคราะห์คะแนนตามมิติ:
  * **Goal Completion:** ได้เครื่องดื่มที่ต้องการหรือไม่
  * **Efficiency:** ใช้จำนวน Turn ในการสั่งซื้อน้อยหรือมากเกินไป
  * **Politeness & Clarity:** มีความสุภาพและชัดเจนเพียงใด
* แสดงหน้าสรุปผลหลังจบสถานการณ์ (Post-Scenario Debrief)

### เฟสที่ 4: ขยายสถานการณ์ในชีวิตประจำวัน (สัปดาห์ที่ 7+)
* ขยายสู่สถานการณ์อื่น: ร้านสะดวกซื้อ, การซื้อตั๋วรถไฟฟ้า, การสอบถามทาง, และการติดต่อสถานพยาบาล

## 6. เครื่องมือและเทคโนโลยีที่แนะนำ (Tech Stack)

* **Front-End:** Next.js (React) + Tailwind CSS + Lucide Icons
* **Voice Processing:** 
  * STT: Web Speech API (Client-side low latency) หรือ Whisper API
  * TTS: Web Speech Synthesis API หรือ ElevenLabs / Google Cloud TTS
* **Back-End Orchestration:** FastAPI (Python) หรือ Node.js (Express/NestJS)
* **AI Engine:** LLM รองรับ JSON Mode / Structured Outputs (เช่น Gemini API หรือ OpenAI API)
* **Database:** PostgreSQL (เก็บบันทึกประวัติและผลการประเมินของผู้เรียน)

## 7. ตัวอย่าง Prompt Template สำหรับบาริสต้า (System Prompt)

```text
คุณคือ "บาริสต้าประจำร้านกาแฟ" ในระบบจำลองสถานการณ์เพื่อการเรียนรู้
เป้าหมายของคุณคือตอบสนองต่อผู้เรียนอย่างเป็นธรรมชาติและสมจริงตามหลักการดังนี้:

1. บริบทอินพุต:
   - ผู้เรียนอาจพูด, พิมพ์, หรือชี้ที่ป้ายเมนู (Point Action)
   - หากผู้เรียนชี้เมนู ให้ถือว่าเขาสนใจเมนูนั้นแม้ไม่ได้เอ่ยชื่อออกมา

2. กฎการตอบสนอง:
   - สุภาพ กระชับ เป็นมิตร เหมือนบาริสต้าตัวจริง
   - หากข้อมูลไม่ครบ (เช่น บอกแค่ "กาแฟ" ไม่ระบุร้อน/เย็น หรือชนิด) ให้ถามเจาะจงอย่างสุภาพ
   - ห้ามเฉลยคำตอบตรงๆ ให้เปิดโอกาสให้ผู้เรียนได้คิดและตอบเอง
   - เมื่อข้อมูลครบถ้วน (ชนิด, อุณหภูมิ, ไซส์) ให้สรุปยอดและส่งสัญญาณว่า Order สำเร็จ

3. การส่งข้อมูลกลับ:
   - ส่งบทสนทนาที่พูดกับผู้เรียน
   - อัปเดต Slot สถานะออเดอร์ในรูปแบบ JSON
```
